# `ssk_run_control_check` Skill Design

## Summary

Create a local repo skill that tells an AI agent how to run `ssk_run_control_check`
for a single Secure SketCH control and then produce a clean auditor-facing Word
report in the same artifact folder as the existing Markdown and JSON outputs.

This skill does not change the MCP tool contract. The MCP tool remains responsible
for:

- running the mapped automated checks
- writing `check.md`
- writing `result.json`
- recording the control-check evidence row in the KB

The skill adds an agent-driven presentation layer on top of those artifacts.

## Goals

- Give future agents a repeatable, explicit workflow for running one control check.
- Preserve fail-loud behavior and avoid fabricated evidence.
- Produce a clean `.docx` report suitable for auditors and internal review.
- Keep all artifacts for a single run in one folder.

## Non-Goals

- Do not modify `ssk_run_control_check` to generate Word output directly.
- Do not add a live UI or auditor portal.
- Do not infer control compliance beyond what the mapped automated checks actually tested.
- Do not silently substitute other scans when a control has no automated mapping.

## Skill Scope

The skill will live under `.agents/skills/` and will instruct an agent to:

1. run `ssk_run_control_check(control_id, generated_by="Dave Lafferty", notes=None)`
2. inspect the returned payload
3. stop on any reported error
4. read the generated `result.json`
5. create a clean `.docx` report in the same run folder
6. report the outcome with exact artifact paths

## Inputs

- `control_id` — required Secure SketCH control ID or valid alias
- `generated_by` — optional, default `Dave Lafferty`
- `notes` — optional operator note to carry into the run and the final report

## Existing Tool Contract

The skill assumes the current tool behavior:

- tool: `ssk_run_control_check`
- output folder: `reports/control-checks/<control_id>/<timestamp>/`
- existing files:
  - `check.md`
  - `result.json`
- returned payload includes:
  - `control_id`
  - `title`
  - `generated_at`
  - `generated_by`
  - `status`
  - `tool_results`
  - `findings`
  - `linked_finding_ids`
  - `evidence_id` for automated runs
  - `output_dir`

## Word Report Contract

The skill must produce one `.docx` file in the same run directory.

Filename rule:

- `<control_id>-<YYYY-MM-DD>.docx`

Location rule:

- `reports/control-checks/<control_id>/<timestamp>/<control_id>-<YYYY-MM-DD>.docx`

Date source:

- derive `YYYY-MM-DD` from the tool's `generated_at` timestamp, not from the local
  clock, so the file name matches the recorded run.

## Report Shape

The Word document should be a clean auditor memo, not a raw Markdown conversion.

Required sections:

1. Title
   - `Secure SketCH Control Check <control_id>`
2. Run summary
   - control title
   - generated date/time
   - generated by
   - final status
3. Executive summary
   - short plain-language statement of what was checked and what the result means
4. Tools run
   - list of mapped automated tools that were executed
5. Findings summary
   - total findings
   - severity mix if findings exist
6. Detailed findings
   - one readable entry per finding with:
     - finding ID
     - severity
     - finding type
     - object name
     - recommended action
     - current status
7. Evidence record
   - evidence ID when present
   - note that the KB evidence points to `result.json`
8. Artifact locations
   - `check.md`
   - `result.json`
   - this `.docx`
9. Operator notes
   - only when `notes` is non-empty

## Status Semantics

The skill must preserve tool semantics exactly:

- `pass`
  - mapped automated checks ran and the control currently has no linked open findings
- `warn`
  - mapped automated checks ran and linked open findings exist
- `manual_required`
  - no automated mapping exists for that control

For `manual_required`, the skill must still create the Word report. The report must
state clearly that:

- no automated control check exists for this control
- no pass/warn conclusion was established by automation
- manual evidence is required

## Failure Handling

The skill must fail loud.

Stop and report the exact issue when:

- `ssk_run_control_check` returns `error_type`
- the tool reports an auth or API failure
- `result.json` is missing
- the returned `output_dir` is missing
- the payload is malformed or missing required fields
- Word report generation fails

The skill must not:

- invent findings
- downgrade an error into a warning
- claim a control passed when the tool did not return `pass`

## Output Rules For The Agent

After the run, the agent should report:

- control ID and title
- final status
- tools run
- finding count
- evidence ID when present
- exact paths to:
  - `check.md`
  - `result.json`
  - generated `.docx`
- any trust warning if the control-to-tool mapping appears questionable

## Implementation Notes

The skill should prefer existing local document tooling and repo conventions rather
than inventing a new reporting framework. The `.docx` generation step should be
kept simple and deterministic so future agents can reproduce it reliably.

1. a new local skill under `.agents/skills/`
2. explicit instructions for calling `ssk_run_control_check`
3. a `.docx` generation path that renders the clean auditor memo into the run folder
