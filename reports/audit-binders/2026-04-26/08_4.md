# 08-4 — Establishing and adopting password policies

**Category:** 08
**Source version:** 2026-01-01
**Current maturity:** not_regularly_reviewed
**Target maturity:** Regularly Reviewed
**Last reviewed:** never
**Next review due:** not scheduled

## MCNA Position

**Regularly Reviewed:** The password policy is regularly reviewed

## Control Statement

Establish and adopt the password strength required for each system and the frequency to be updated

_No evidence linked._

## Recommended Actions

| ID | Action | Status | Owner |
|----|--------|--------|-------|
| 08-4-a | Set a password policy | not_started | — |
| 08-4-b | When notifying the password to the user, establish rules such as verifying the recipient's identity | not_started | — |
| 08-4-c | Ensure that the initial temporary password issued and communicated to the user is changed | not_started | — |
| 08-4-d | Always change default password present in new systems ("factory reset" versions of password must be changed before putting in use) | not_started | — |
| 08-4-e | Disallow the use of the same password for some iterations of password changes (password history) | not_started | — |
| 08-4-f | Use a different password for each system | not_started | — |
| 08-4-g | Require a password whose strength is in accordance with the security requirement level (privileged access, high-level access, general access, etc.) | not_started | — |
| 08-4-h | Set the password strength higher if multi-factor authentication is not available for highly privileged accounts, such as administrator accounts | not_started | — |
| 08-4-i | Systematically controlled in accordance with an established policy, or the policy is thoroughly complied with | not_started | — |
| 08-4-j | Regularly review password policies | not_started | — |
