## Summary

The KB contains 31 open EXO findings. 30 are High findings where a mailbox is classified as `userPurpose=shared` but the underlying Entra account is still enabled.

That state is a real risk. Shared mailboxes should be accessed by delegated users, not by signing in directly as the mailbox account. Enabled shared mailbox accounts create an avoidable credential target and a lateral-movement path.

Recommended remediation:

1. Disable the underlying Entra account for confirmed shared/function mailboxes.
2. Validate device, automation, infrastructure, and unclear former-user mailboxes before changing them.
3. Re-run `exo_scan_mailboxes` after changes.
4. Resolve KB findings only after the scan confirms `accountEnabled=false`.

No tenant changes were made while producing this worksheet.

Suggested portal path:

`Entra admin center > Users > select user > Edit properties > Account enabled = No`

2. Confirm each remediated mailbox snapshot has `userPurpose=shared` and `accountEnabled=false`.
3. Resolve the matching KB finding with a note that the account was disabled and verified by the scan.
